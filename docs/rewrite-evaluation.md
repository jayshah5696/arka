# Evaluate Arka selection on a rewrite task

The question is whether choosing examples with Arka improves rewrites at the same training cost. A higher judge score on selected training examples cannot answer it.

1. Reserve real rewrite requests before generating examples. Include the original passage, edit requested, facts to preserve, and required output format. Keep each seed and its descendants together using `lineage.root_id`. Group PDF examples by `source.doc_id` to keep overlapping chunks together. Remove exact duplicates across partitions and inspect near matches.
2. Generate one candidate pool. Save its generator-stage Parquet artifact and the final selected artifact. Sample the baseline from the full pool with a recorded random seed. Draw both training sets only from training families. Save record IDs, root IDs, and the artifact hashes so another run can recover the selection.
3. Render both training sets with the same pinned model revision, tokenizer, and chat template. For completion-only SFT, split each conversation into a conversational `prompt` (all preceding messages) and `completion` (the final assistant message). Inspect the trainer's actual labels on a short example and a truncated example. Verify that the expected answer has supervised tokens. Count non-padding input tokens and supervised tokens separately.
4. Evaluate the base model before training. Fine-tune two copies with identical optimizer, adapter settings, seed, truncation, and batch size. Use the same number of training tokens in each arm. Record actual token counts, selection cost, and training time. Evaluate all three checkpoints on the reserved prompts with identical decoding settings.
5. Shuffle and blind the outputs. Check required format and named facts for each prompt. Ask reviewers which rewrite best follows the request, allowing ties. Report the per-prompt wins, ties, losses, format pass rate, and fact errors. Estimate uncertainty by resampling held-out seed families. Report the size of the holdout and unresolved reviewer disagreements.

## Reproduce the comparison

Use the following reference protocol for the first run. Choose the real request corpus and affordable training-token ceiling when compute is available. Freeze both choices before reviewing model outputs.

- **Split.** Assign each original request a stable family ID before generation. Related requests about the same passage share that ID. Order families by the hexadecimal SHA-256 of the UTF-8 string `arka-rewrite-v1/holdout/<family_id>`. Reserve the first 20% of families, rounding up. Keep at least one family for training. Archive the actual split and dataset revision.
- **Match the budget.** Render and truncate every training candidate once. Discard rows with zero supervised tokens. Group the candidate pool by exact non-padding input length. Order selected rows by the SHA-256 of `arka-rewrite-v1/selected/<record_id>`, taking whole rows that fit the remaining token ceiling. For each length, draw the same number of baseline rows from the full pool in hash order using `arka-rewrite-v1/baseline/<record_id>`. Sample without replacement within each arm. A baseline row may also be selected. This control holds row count and input tokens constant and measures selection beyond its effect on length. Report overlap and supervised-token totals. If both lists are identical, the comparison has no selection difference to measure.
- **Run.** Save the ordered training IDs for both arms. Train each for one pass with the same seed and batch settings. Store the resolved trainer configuration, dependency lock, base model and tokenizer revisions, chat-template hash, hardware, and checkpoint hashes. Generate one rewrite per held-out prompt per checkpoint with greedy decoding and the same recorded output limit.
- **Score.** Make the selected-versus-random comparison primary. Present each output pair in a reproducibly shuffled order, hide the checkpoint names, and save the reveal key separately. Count a selected win as 1, a tie as 0.5, and a loss as 0. Average within each held-out family, then average across families. Report the score alongside the raw counts and a 95% percentile interval from 10,000 family bootstrap draws with seed 42. Record factual and format failures separately. Report both tuned-versus-base comparisons as secondary results.

To replay a completed experiment, verify the saved input hashes, reproduce the ordered ID lists and token totals, and apply the recorded trainer and decoding configurations. The saved blind ballots and reveal key should reproduce the reported scores without generating new outputs.
