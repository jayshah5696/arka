# Arka Pull Request Review (May 20, 2026)

We checked the three currently open pull requests on the repository. Since PR #49 was recently merged, it introduced a unified sequential pipeline configuration layout, updating a large part of the configuration parsing and validation. Below is our analysis and recommendation for each PR.

---

## 1. PR Analysis

### PR #46: Bolt: CheckpointManager uses single thread-safe WAL connection
- **Branch**: `bolt-sqlite-wal-mode-4-17159828799158118208`
- **Status**: **Obsolete / Already Merged**
- **Analysis**:
  - The core WAL mode checkpointing optimization (persistent SQLite connection with WAL journal mode and normal sync settings) was already successfully merged into `main` in commit `22fd13b` (#33).
  - The other bugfixes (e.g., parameter alignment in `double_critic_stage.py` and old test configurations) have either been integrated or superseded by the sequential config schema migration in PR #49.
- **Recommendation**: Close without merging.

### PR #47: Palette: [DX improvement] Improve ConfigValidationError messages
- **Branch**: `palette-dx-improvement-923220463444613966`
- **Status**: **Important DX Improvement (Partially Pending)**
- **Analysis**:
  - This PR formats raw Pydantic validation errors (specifically `missing` and `extra_forbidden` types) to be more human-readable:
    - `Missing required field: 'llm'` instead of `llm: Field required`
    - `Unknown field: 'random_key' (this key is not allowed here)` instead of `random_key: Extra inputs are not permitted`
  - While PR #49 added a custom validator formatter, it still outputs the raw Pydantic messages (`- field: msg`).
- **Recommendation**: Port the user-friendly validation error mapping into `src/arka/config/loader.py`.

### PR #48: Palette: Add execution duration tracking to pipeline run summary
- **Branch**: `palette/dx-pipeline-duration-16117302771492360774`
- **Status**: **Important DX Improvement (Pending)**
- **Analysis**:
  - This PR measures the total execution time of the pipeline CLI execution and prints the formatted duration (e.g., `Duration: 1.5s` or `Duration: 1m 20.3s`) in the CLI run summary.
  - This is not yet on the `main` branch.
- **Recommendation**: Port the duration tracking logic to `src/arka/cli.py`.

## 2. Action Plan

We propose to solve/port the remaining valuable DX improvements from PR #47 and PR #48. Here are the specific changes to be made:

### A. Port PR #47 Config Validation Improvement
In `src/arka/config/loader.py`, format the errors dynamically based on error type:
```python
err_type = error.get("type")
if err_type == "missing":
    msg = f"Missing required field: '{path}'"
elif err_type == "extra_forbidden":
    msg = f"Unknown field: '{path}' (this key is not allowed here)"
else:
    msg = f"Invalid value for '{path}': {msg}"
lines.append(f"  - {msg}")
```

### B. Port PR #48 CLI Duration Tracking
In `src/arka/cli.py`:
1. Import `time`.
2. Wrap `main()` with a start timer and compute `duration_secs = time.time() - start_time`.
3. Update `_print_summary(run_id, project_root, duration_secs: float | None = None)` to format and display the execution duration.
