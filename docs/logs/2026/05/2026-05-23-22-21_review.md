## 2. Exploration & Findings

We analyzed `src/arka/` and identified two major architectural friction points:

1. **`StageBuilder` coupling (Shallow Module):**
   * **Files:** `src/arka/pipeline/stage_builder.py`
   * **Problem:** `StageBuilder` has to manually import every single stage type and stage config class to map configuration schema types to concrete implementations, causing high coupling and violating the Open-Closed Principle.
   * **Proposed Solution:** Introduce a Stage Registry where stage classes register themselves. `StageBuilder` dynamically builds stages by resolving registry lookups, transforming it into a decoupled, deep module.

2. **Filter Boilerplate Duplication (Shallow Stack):**
   * **Files:** `src/arka/pipeline/cheap_filters.py`, `src/arka/pipeline/filter_stages.py`
   * **Problem:** Every filter stage (Length, Language, SentenceVariance, Canary, etc.) duplicates the record iteration logic, type checks, `dropped_by()` scoring, and artifact writing boilerplate.
   * **Proposed Solution:** Implement a `BaseFilterStage` that implements the standard run loop, record traversal, drop handling, and telemetry logging/writing. Subclasses then only need to supply a simple boolean predicate or drop-reason checker.
