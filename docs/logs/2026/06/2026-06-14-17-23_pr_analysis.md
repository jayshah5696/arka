## Group 1: Security & Sentinel Fixes

This group addresses critical vulnerabilities, including information exposure (API keys) and prompt injections.

### PR 76: Sentinel: [MEDIUM] Information Exposure via LLM API Error Stack Traces
* **Branch**: `sentinel-fix-llm-tracebacks-9130562004234857355`
* **Vulnerability**: Catching OpenAI/LLM errors using `from exc` leaks `httpx.Request` context (including authorization headers containing API keys) in the traceback.
* **Fix**: Raises custom `LLMClientError` `from None` in `src/arka/llm/client.py` and documents the vulnerability in `.jules/sentinel.md`.
* **Recommendation**: **MERGE**. This implementation is clean, adds security-focused documentation, and includes comments highlighting the reasoning.

### PR 80: Sentinel: [HIGH] Exceptions leaking HTTP request contexts
* **Branch**: `sentinel-stack-trace-leak-11461445662911557365`
* **Vulnerability**: Same as PR 76.
* **Fix**: Replaces `from exc` with `from None` in `src/arka/llm/client.py`.
* **Conflict & Regression**: PR 80 was branched from an older commit and contains a regression that deletes two existing, unrelated sentinel entries in `.jules/sentinel.md` (API Key Leakage via StageLLMOverride and Prompt Injection via Seed Data).
* **Recommendation**: **IGNORE / REJECT** in favor of PR 76.

### PR 77: Sentinel: [HIGH] Prompt injection in pipeline stages
* **Branch**: `sentinel-prompt-injection-13569024221574578198`
* **Vulnerability**: Direct insertion of untrusted user seeds into LLM prompts in generator and critic stages.
* **Fix**: Uses `sanitize_for_prompt` to recursively remove XML-like tags, wraps untrusted user data in `<text>` tags, and instructs the LLM system prompt to ignore instructions inside them.
* **Recommendation**: **MERGE**. Critical security hardening for synthetic SFT data generation.

## Group 4: Stage Failure Reporting & Record Loss

This group targets how stage failures and record counts are reported in `runner.py` and `cli.py`.

### PR 79: Palette: Clarify lost records on stage failure
* **Branch**: `dx-clarify-lost-records-6996265720826868203`
* **Fix**: Sets `count_out=0` on stage failure in `runner.py` (preventing the system from falsely reporting that a failed stage yielded records equal to the input). In `cli.py`, it prints `(lost X records)` when a stage status is `failed`.
* **Recommendation**: **MERGE** core logic. Highly superior to PR 81 because of the explicit CLI output enhancement.

### PR 73: Palette: [DX improvement] Print final pipeline error message after summary for better visibility
* **Branch**: `dx-cli-error-summary-764282504612777483`
* **Fix**: Refactors exception handling in `cli.py` to defer printing the pipeline execution error until *after* the summary has finished printing (making it the very last output on screen). Wraps summary printing in `try-except` to prevent failures there from swallowing the main pipeline error.
* **Recommendation**: **MERGE**. Excellent DX improvement that prevents errors from being buried under scrollback.

### PR 68: Palette: Surface failed stage errors in CLI summary
* **Branch**: `palette-cli-error-summary-7900977684005396704`
* **Fix**: Prints the specific stage error details (`Failed: {type}: {message}`) directly below the failed stage row inside `_print_summary`.
* **Recommendation**: **CONSOLIDATE**. This is useful, but should be integrated alongside the summary enhancements of PR 79 and PR 73 to avoid duplicate printouts.

### PR 71: Palette: improve pipeline summary and failure reporting
* **Branch**: `dx-improve-cli-summary-failure-logging-6438566464750920321`
* **Fix**: Prints the output dataset path on success, sets `count_out=0` on failure, and raises `RuntimeError` including a lost record count.
* **Conflict & Redundancy**: The `count_out=0` and failure message changes overlap/conflict with PR 79 and PR 78.
* **Recommendation**: **CONSOLIDATE / CHERRY-PICK** only the dataset output path display feature into the main branch; reject the duplicate error formatting changes.

### PR 78: Palette: Improve CLI error reporting DX
* **Branch**: `palette/cli-error-reporting-dx-9803551758433265829`
* **Fix**: Same exception deferral as PR 73 and raises `RuntimeError` processing count.
* **Conflict**: Direct conflict with PR 73.
* **Recommendation**: **IGNORE / REJECT** in favor of PR 73, which features a safer `try-except` wrapper around the summary print step.

### PR 81: Palette: Ensure failed stages report zero output records
* **Branch**: `palette-fix-failed-stage-count-6636710479828897928`
* **Fix**: Sets `count_out=0` on stage failure in `runner.py` and updates tests.
* **Conflict & Redundancy**: Completely redundant with PR 79 (which does this and more).
* **Recommendation**: **IGNORE / REJECT** in favor of PR 79.
