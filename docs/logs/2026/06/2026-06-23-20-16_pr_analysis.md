## Group 1: Security Hardening

This group addresses input sanitization and security vulnerabilities.

### PR 90: Fix prompt injection vulnerability in seed ingestion
* **Branch**: `sentinel-prompt-injection-fix-2577735367420460192`
* **Vulnerability**: Direct insertion of raw, un-sanitized seed data (JSONL/CSV format) into pipeline payloads. If malicious seed instructions are ingested, they can bypass downstream prompt sanitization checks and inject prompt instructions that manipulate generator or judge LLMs.
* **Fix**: Wraps seed inputs inside `SeedSourceStage._build_record` in `src/arka/pipeline/source_stages.py` with `sanitize_for_prompt()`. It also documents the vulnerability threat model and resolution in `.jules/sentinel.md`.
* **Recommendation**: **MERGE (with cleanup)**. This is a critical security fix. However, the PR includes `uv.lock` modifications deleting `exclude-newer` configs, which should be discarded as lockfile slop.

## Group 3: Stage Failure & Config Error visibility (Overlaps & Redundancies)

This group focuses on displaying lost records on stage failure and format improvements for config validation errors.

### PRs 87, 88, 89, 92: Include lost record counts in stage failure error message
* **Branches**: 
  - PR 87: `palette-improve-stage-failure-error-message-16957163190610408552`
  - PR 88: `palette-dx-stage-failure-error-6086271515763288309`
  - PR 89: `palette-dx-improvement-llm-error-message-2657684222828615687`
  - PR 92: `palette-dx-stage-loss-cli-1185592405742062798`
* **Details**: All four PRs modify the `RuntimeError` raised in `runner.py` on stage failure to append `.{count_in} records were lost.`.
* **Grammar Flaw**: All four print `"1 records were lost."` when exactly one record fails.
* **Lockfile Slop**: PR 88 and PR 92 contain unnecessary `uv.lock` modifications.
* **Recommendation**: **IGNORE / REJECT** in favor of a consolidated and corrected implementation (see PR 93 recommendation below).

### PR 93: Palette: Error visibility formatting in cli config errors and pipeline stage failures
* **Branch**: `palette-dx-improvements`
* **Details**: This PR consolidates two changes:
  1. Appends the same `{count_in} records were lost.` message to the stage failure `RuntimeError`.
  2. Prefixes raw `ConfigValidationError` outputs in `src/arka/cli.py` with `"Error: "` for faster visibility, alongside a test checking this output format.
  3. Adds a summary log to `.jules/palette.md`.
* **Workspace Slop**: Contains numerous backup and diff files committed to the branch:
  - `patch_runner.diff`
  - `patch_tests.diff`
  - `src/arka/cli.py.orig`
  - `src/arka/pipeline/runner.py.orig`
  - `tests/unit/test_cli.py.orig`
  - `uv.lock` changes.
* **Grammar Flaw**: Prints `"1 records were lost."` when `count_in == 1`.
* **Recommendation**: **BETTER IMPLEMENTED (Consolidated)**. We should merge the core features of PR 93 (both the `Error: ` prefix and the stage failure record count), but rewrite them with two critical improvements:
  1. **Fix Grammar**: Handle singular/plural record strings:
     `f"Stage '{stage.name}' failed - {exc}. {count_in} record{' was' if count_in == 1 else 's were'} lost."`
  2. **Sanitize Workspace**: Discard all backup (`.orig`), local diff (`.diff`), and `uv.lock` files to keep the git history clean.
