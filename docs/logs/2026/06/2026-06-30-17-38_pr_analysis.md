## Group 3: Cache ResolvedConfig hash computation (Overlaps & Redundancies)

This group caches the SHA-256 config hash to optimize CPU overhead during pipeline execution.

### PR 99: Bolt: [Optimize config hash computation]
* **Branch**: `pr/99`
* **Design flaw**: Computes the hash eagerly at load time in `ConfigLoader`. This introduces a dependency from `loader.py` to `arka.records.identity`, risking circular imports since `identity.py` already imports `ResolvedConfig` from config models.
* **Recommendation**: **IGNORE / REJECT** in favor of lazy caching.

### PR 100 & PR 103: Cache config hash computation on ResolvedConfig object
* **Branches**:
  - PR 100: `perf/sqlite-wal-checkpoint-2193864406944262106`
  - PR 103: `perf-openai-connection-pooling-2116396656599668755`
* **Details**: Both introduce a `_computed_hash: str | None = PrivateAttr(default=None)` on `ResolvedConfig` and cache the hash lazily in `config_hash(config)` in `identity.py`, reducing computation from O(N) to O(1) without touching the loader.
* **Recommendation**: **MERGE PR 100 (with cleanups)**. Discard the `uv.lock` changes.
