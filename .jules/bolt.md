## 2025-02-18 - NearDedupStage O(n^2) bottleneck / Learning: Minhash signatures were being recomputed within a nested loop and evaluated against every representative. / Action: Added LSH bucketing (lsh_bands config option) to segment signatures and restrict Jaccard similarity comparisons to matching bucket candidates, turning an O(n^2) operation into O(n) average case.
## 2025-04-22 - fastembed embedding cache / Learning: Model embedding operations were being recomputed entirely on `--resume` runs. / Action: Implemented SQLite-backed embedding caching in `CheckpointManager` and injected it into `PipelineRunner._embed_texts`, leveraging existing state DB to eliminate recomputes.
## 2025-05-28 - OpenAI Client Connection Pooling / Learning: Repeated creation of `openai.OpenAI` clients across stages forces expensive TLS handshake and TCP connection setup overheads for every batch. / Action: Implemented an in-memory `_client_cache` in `src/arka/llm/openai_client.py` using a lock and configuration tuple to keep connections alive and pooled across batch executions.
## 2026-06-09 - ThreadPoolExecutor reuse across stages / Learning: Repeatedly creating `ThreadPoolExecutor` inside individual pipeline stages (`DoubleCriticFilterStage`, `ComplexityEloScoringStage`) for batch workloads incurs significant thread spawn/destroy overhead. / Action: Added an `executor` field to `StageContext` and initialized a single `ThreadPoolExecutor` in `PipelineRunner.run` using a context manager to pool threads across the entire pipeline execution.
## 2024-06-16 - Cache HuggingFace fastembed model / Learning: fastembed TextEmbedding initialization was redundantly loading weights from disk on every execution. / Action: In the future, cache computationally expensive initializations using locks and dictionaries within the ThreadPoolExecutor architecture.
